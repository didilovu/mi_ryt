# Мой ритм

Локальное мобильное приложение домашних тренировок: React 19, TypeScript, Vite, Tailwind CSS 4, Lucide React, Recharts, IndexedDB (`idb`). Сервер, аккаунт и внешние API не нужны. В репозитории нет демонстрационных измерений или истории.

## Запуск на Windows в VS Code

1. Установите Node.js **22.12+** (или 24 LTS) и VS Code.
2. Откройте папку проекта в VS Code, выберите «Терминал → Создать терминал».
3. Выполните:

```powershell
npm ci
npm run dev
```

Откройте адрес, который напечатает Vite. Остановить сервер: `Ctrl+C`.

Проверки и рабочая сборка:

```powershell
npm test
npm run build
npx playwright install chromium
npm run test:e2e
npm run preview
```

Браузерные тесты используют системный Chromium в Linux, если он есть, иначе браузер Playwright. Перед ними нужна свежая сборка `npm run build`. Service worker включён только в рабочей сборке, чтобы старый кэш не мешал разработке.

## Телефон и установка на iPhone

- Для просмотра разработки подключите телефон и компьютер к одной Wi-Fi-сети. `npm run dev` слушает сетевые интерфейсы. Откройте на телефоне адрес компьютера с портом Vite (обычно 5173). При необходимости разрешите Node.js в частной сети брандмауэра Windows.
- Обычный HTTP по адресу компьютера подходит для просмотра, **но не для установки PWA и офлайн-кэширования**: браузеры требуют защищённый контекст.
- Для PWA разместите **содержимое `dist/`** на статическом HTTPS-хостинге (в корне или подпапке домена). Никакой серверной обработки данных не требуется. Сначала полностью загрузите приложение онлайн; дождитесь статуса «Доступно офлайн», затем проверьте его в авиарежиме.
- iPhone: откройте HTTPS-адрес в Safari → «Поделиться» → «На экран “Домой”» → «Добавить». Android: меню Chrome → «Установить приложение» / «Добавить на главный экран».
- Данные привязаны к браузеру и адресу сайта. Перед сменой адреса или переносом в установленное приложение экспортируйте JSON, затем импортируйте его при необходимости. В приватном режиме долговременное хранение может быть недоступно.

## Что реализовано

- Пять разделов нижней навигации, мобильная компоновка, safe areas, русские подписи, светлая/тёмная тема и поддержка `prefers-reduced-motion`.
- Структурированная четырёхнедельная программа: четыре обязательных дня, отдых и включаемая пятая практика. На первой неделе уменьшены подходы; круги кардио — 3/4/5/5. Каждая тренировка содержит разминку и заминку.
- Пошаговый плеер: ручной старт и подтверждение подхода, повторения или интервал, отдых, пауза, пропуск, досрочное завершение и сохранение частичного результата. Истечение таймера **не подтверждает** подход.
- 25 упражнений: отдельные локальные SVG-схемы исходного и следующего положения, последовательное подсвечивание с остановкой, техника, ошибки и облегчённая версия. Поиск и фильтр библиотеки.
- Календарь месяца: пять статусов, выбор дня, запуск, перенос/обмен тренировок и изменение отдыха. Будущие занятия не считаются пропущенными, история не переносится вместе с планом.
- Профиль: возраст, рост, вес и цели. Все поля необязательны, редактируются; возраст и рост не входят в расчёт калорий.
- Реальные измерения с датой: вес, талия и бёдра, графики и удаление ошибочной записи. Вес измерения не заменяет текущий вес профиля автоматически.
- История, время занятий, выполнение плана, недельный прогресс, достижения по сохранённым завершённым тренировкам. Достижение месяца требует занятия в каждой из четырёх недель и завершённой тренировки не раньше 28-го дня программы.
- MET-расход во время занятия и в истории, недельные/месячные суммы и дневной график. Отсутствие веса отображается как «Нет данных». В смешанных итогах показана сумма известных оценок и число записей без оценки.
- IndexedDB, восстановление текущей тренировки на паузе, экспорт/импорт JSON с проверкой структуры и подтверждением замены, сброс прогресса с подтверждением. Импорт текущей тренировки также восстанавливает её на паузе.
- PWA: manifest, PNG-иконки, локальный service worker, версионирование кэша по сборке, предварительное кэширование всех ресурсов приложения. Ресурсы и пользовательские данные не зависят от CDN.

## Расчёт времени и энергии

`ккал = MET × 3,5 × вес_кг / 200 × активные_минуты`.

Источник категорий: **2011 Compendium of Physical Activities**, раздел _Conditioning exercise_: [справочник](https://sites.google.com/site/compendiumofphysicalactivities/Activity-Categories/conditioning-exercise). Также: Ainsworth et al., _2011 Compendium of Physical Activities: a second update of codes and MET values_, DOI: `10.1249/MSS.0b013e31821ece12`.

Использованы категории: умеренная калистеника — **3,8 MET**, лёгкая — **2,8**, интенсивная — **8,0**, мягкая растяжка — **2,3**. Соответствие упражнения категории указано в `src/data.ts`; это приближение к интенсивности категории, а не лабораторное измерение конкретного движения. Для облегчённого варианта в плеере можно отключить оценку до конца тренировки.

- Активность повторений измеряется таймером между стартом и подтверждением. Повторения **не переводятся в минуты** для калорий.
- Интервал учитывается до целевой длительности, затем таймер ждёт ручного подтверждения; ожидание не активно.
- Пауза, ожидание и отдых записываются отдельно; для них этот счётчик не оценивает расход энергии. Он не отражает базовый или суточный расход организма.
- Пропуск исключает текущий незавершённый подход и оставшиеся подходы; уже подтверждённая работа остаётся в истории. Досрочное завершение сохраняет активную часть текущего подхода, не помечая его выполненным.
- История содержит массу, MET каждого подхода, длительность, источник и итог; изменение профиля её не пересчитывает.
- Оценки не вычитаются из нормы питания и не являются медицинскими измерениями.
- Плановая продолжительность учитывает все подходы и отдых. Для повторений используются **только плановые** оценки длительности (примерно 3–4 с/повторение); поэтому показано `~`, а не фиксированные 40 минут. Фактическая история использует таймер. Гибкость — 40 минут, воскресная практика — 30 минут; силовые дни и круги различаются по неделям.

## Структура

```text
src/
  model.ts          типы профиля, расписания, сессии и истории
  data.ts           упражнения, MET, программа и недельная прогрессия
  engine.ts         локальные даты, календарь, переходы таймера и расчёты
  storage.ts        IndexedDB и валидация резервных копий
  ExerciseDemo.tsx  SVG-схемы движений и управление показом
  audio.ts          разблокировка звука пользовательским действием
  App.tsx           экраны, формы и сохранение состояния
  main.tsx          точка входа и регистрация PWA
  style.css         адаптивный дизайн, темы и доступность
public/             manifest, service worker и иконки
 tests/             логические тесты и браузерные сценарии
```

## Проверки и ограничения

Проверены сборка TypeScript/Vite, логические тесты и Chromium-сценарии: мобильная навигация, профиль, фактическая активность, отдых, восстановление после перезагрузки, частичная история, неизменность исторического веса, библиотека, измерения, экспорт, отказ повреждённому импорту и перезагрузка без сети.

- Физические iPhone/Android и мобильный Safari в этой среде не проверены. Нужна итоговая проверка установки на устройствах.
- Схемы — двухкадровые инструкции, а не непрерывная биомеханическая анимация или контроль техники. Пользуйтесь текстом; для сложных движений стороны чередуются самостоятельно.
- При сворачивании приложение автоматически ставит тренировку на паузу. Время с закрытым приложением не начисляется. Фонового таймера, push-уведомлений и гарантированного звука на заблокированном телефоне нет.
- Запись идёт при действиях и каждые 0,5 с; при аварийном завершении процесса возможна потеря последнего незаписанного интервала. Ошибки чтения не заменяют существующие данные пустыми, ошибки записи отображаются.
- JSON-импорт заменяет данные после подтверждения, а не объединяет их. Копии не зашифрованы. Сохраните экспорт перед импортом и очисткой браузера.
- Для публикации подготовлена отдельная ветка `gh-pages` со сборкой. Включение GitHub Pages выполняется владельцем репозитория в настройках, как описано ниже.

## Самый короткий путь установки на iPhone — GitHub Pages

Готовая сборка помещена в ветку `gh-pages` репозитория. Ветка `work` содержит исходники.

1. Откройте https://github.com/didilovu/mi_ryt/settings/pages под своим GitHub-аккаунтом.
2. В **Build and deployment → Source** выберите **Deploy from a branch**.
3. В **Branch** выберите **gh-pages**, папку **/(root)** и нажмите **Save**.
4. Дождитесь успешной публикации (обычно несколько минут). Настройки Pages покажут адрес сайта: https://didilovu.github.io/mi_ryt/ . До публикации адрес может показывать 404.
5. Откройте адрес сайта на iPhone именно в **Safari**, дождитесь полной загрузки.
6. Нажмите **Поделиться** (квадрат со стрелкой вверх) → **На экран «Домой»** → **Добавить**. Если пункт не виден, прокрутите список действий ниже.
7. Открывайте «Мой ритм» с появившейся иконки. После первой полной загрузки сборка доступна без сети.

GitHub Pages делает интерфейс сайта доступным по ссылке. Ваш профиль и тренировки остаются в браузере на устройстве и не отправляются в репозиторий.

Если GitHub требует изменить тариф или видимость приватного репозитория для Pages, не меняйте видимость автоматически: используйте совместимый статический HTTPS-хостинг. Для следующих обновлений нужно заново собрать приложение и обновить содержимое ветки `gh-pages`; простое изменение `work` сайт не обновляет.
